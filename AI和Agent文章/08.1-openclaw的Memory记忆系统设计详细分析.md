OpenClaw 的记忆系统非常值得研究，因为它采用了一种与 AutoGPT、MemGPT、LangGraph 完全不同的思路：

> **Memory = 文件系统，而不是数据库。**
>
> Agent 不依赖隐藏状态（Hidden State），而是把记忆显式写入 Markdown 文件，让 LLM 自己读取、总结和更新。 ([OpenClaw](https://docs.openclaw.ai/concepts/memory?utm_source=chatgpt.com))

从 AI Agent 架构角度看，这是一种 **Memory-as-Workspace（记忆即工作空间）** 设计。

------

# 一、OpenClaw记忆系统总体架构

官方设计中主要有三层记忆： ([OpenClaw](https://docs.openclaw.ai/concepts/memory?utm_source=chatgpt.com))

```text
┌──────────────────────┐
│ Session Context      │
│ 当前会话上下文        │
└─────────┬────────────┘
          │
          ▼
┌──────────────────────┐
│ Daily Memory         │
│ memory/YYYY-MM-DD.md │
└─────────┬────────────┘
          │
          ▼
┌──────────────────────┐
│ MEMORY.md            │
│ 长期记忆             │
└──────────────────────┘
```

有些版本还增加：

```text
DREAMS.md
Wiki
Memory Search
```

形成：

```text
Session
   ↓
Daily Notes
   ↓
Long-term Memory
   ↓
Knowledge Base
```

这其实已经接近人脑的：

```text
工作记忆
↓
短期记忆
↓
长期记忆
↓
语义知识
```

------

# 二、核心文件结构

## 1 MEMORY.md

长期记忆库

官方定义：

> Durable facts, preferences, decisions. ([OpenClaw](https://docs.openclaw.ai/concepts/memory?utm_source=chatgpt.com))

典型内容：

```markdown
# User

- 用户喜欢Spring Boot
- 用户是CEO
- 用户关注AI Agent

# Projects

- 正在开发营销AI系统

# Decisions

- MCP作为插件协议
```

特点：

### 持久化

跨会话存在

```text
今天关闭Agent
明天启动Agent

MEMORY.md仍存在
```

------

### 启动自动加载

OpenClaw启动时读取：

```text
MEMORY.md
```

直接注入Prompt。 ([OpenClaw](https://docs.openclaw.ai/concepts/memory?utm_source=chatgpt.com))

即：

```text
System Prompt
+
MEMORY.md
+
Conversation
```

形成上下文。

------

## 2 Daily Memory

目录：

```text
memory/
 ├── 2026-06-10.md
 ├── 2026-06-11.md
```

作用：

记录当天发生的事情。 ([OpenClaw](https://docs.openclaw.ai/concepts/memory?utm_source=chatgpt.com))

例如：

```markdown
# Today

用户讨论微服务监控系统

决定采用：

- OpenTelemetry
- Prometheus
- Grafana
```

------

特点：

### Append Only

只追加

```text
新事件
↓
追加
```

类似日志系统。

------

### 自动读取最近两天

OpenClaw默认会读取：

```text
today
yesterday
```

两个文件。 ([OpenClaw](https://docs.openclaw.ai/concepts/memory?utm_source=chatgpt.com))

这样避免：

```text
365个文件全部加载
```

导致Context爆炸。

------

# 三、记忆写入机制

OpenClaw最大的特点：

## 不是自动记忆

而是：

```text
用户要求记住
↓
Agent决定重要
↓
写文件
```

官方明确指出：

> If someone says “remember this”, write it down. ([Open Claw Lab](https://openclawlab.com/en/docs/concepts/memory/?utm_source=chatgpt.com))

例如：

用户：

```text
记住：
我的项目采用Spring Boot
```

Agent执行：

```python
append("MEMORY.md")
```

写入：

```markdown
- 项目采用Spring Boot
```

# 四、记忆检索机制

这是OpenClaw最巧妙的部分。

仅靠：

```text
加载MEMORY.md
```

很快会变成：

```text
10000行
```

无法使用。

因此官方引入：

```text
Memory Search Plugin
```

机制。 ([Open Claw Lab](https://openclawlab.com/en/docs/concepts/memory/?utm_source=chatgpt.com))

------

## 检索流程

```text
用户提问
↓
Memory Search
↓
找到相关记忆
↓
注入Prompt
↓
回答
```

例如：

用户：

```text
我之前决定用什么监控方案？
```

系统：

```text
memory_search("监控")
```

返回：

```text
2026-06-10.md

OpenTelemetry
Prometheus
Grafana
```

然后加入上下文。

# 五、长期记忆压缩机制

这是Agent系统最关键的能力之一。

因为：

```text
Daily Memory
越来越大
```

需要沉淀。

流程：

```text
Daily Notes
↓
总结
↓
MEMORY.md
```

例如：

每天：

```text
采用Spring Boot
采用MCP
采用Prometheus
```

一个月后：

MEMORY.md

```markdown
# Architecture

- Spring Boot微服务架构
- MCP插件协议
- OpenTelemetry观测体系
```

这就是：

### Episodic → Semantic

情景记忆

转化为

语义记忆

与人脑机制非常接近。 ([Learn OpenClaw - Resource Center](https://resources.learnopenclaw.ai/openclaw-memory-systems-give-your-ai-agent-long-term-memory/?utm_source=chatgpt.com))

# 六、OpenClaw的“Dreaming”机制

较新版本加入：

```text
DREAMS.md
```

官方称为：

```text
Dream Diary
```

记录 Agent 周期性整理后的结果。 ([OpenClaw](https://docs.openclaw.ai/concepts/memory?utm_source=chatgpt.com))

流程：

```text
Daily Logs
↓
Dream Sweep
↓
发现模式
↓
写入DREAMS.md
```

例如：

```markdown
发现：

长期兴趣为Agent架构
```

类似：

```text
睡眠记忆巩固
```

机制。

# 七、为什么OpenClaw不用向量数据库

很多Agent框架：

```text
Conversation
↓
Embedding
↓
Vector DB
↓
Recall
```

OpenClaw故意避免这一方案。 ([OpenClaw](https://docs.openclaw.ai/concepts/memory?utm_source=chatgpt.com))

原因：

### 可解释

你能直接打开：

```text
MEMORY.md
```

看到：

```text
Agent到底记住了什么
```

------

### 可编辑

人工修改：

```markdown
删除错误记忆
```

即可。

------

### Git友好

直接：

```bash
git diff
```

查看变化。

------

### 模型无关

Claude

GPT

Gemini

都能使用。

# 八、从Agent架构角度评价

如果站在企业级 AI Agent 设计角度：

OpenClaw 实际采用的是：

```text
File-based Memory Architecture
```

而不是：

```text
Vector-native Architecture
```

其优势：

| 维度        | OpenClaw |
| ----------- | -------- |
| 可解释性    | 极强     |
| 可审计性    | 极强     |
| 成本        | 极低     |
| 调试        | 容易     |
| Git管理     | 支持     |
| 多Agent共享 | 支持     |

缺点：

| 维度         | 问题       |
| ------------ | ---------- |
| 规模化       | 一般       |
| 检索精度     | 不如向量库 |
| 百万级记忆   | 困难       |
| 自动知识关联 | 弱         |

# 九、如果你要做商业级AI Agent

结合你正在研究的营销AI系统和商业系统，我会采用：

```text
OpenClaw Memory
+
Knowledge Graph
+
Vector Memory
```

形成四层架构：

```text
L1 Session Memory
（当前上下文）

L2 Episodic Memory
（Daily Logs）

L3 Semantic Memory
（MEMORY.md）

L4 Knowledge Graph
（客户/产品/需求关系）
Session
↓
Daily
↓
Summary
↓
Knowledge Graph
```

这实际上已经接近当前先进 Agent（如 MemoryOS、Letta/MemGPT、Graphiti）所采用的长期记忆体系，但 OpenClaw 的优势在于：**用极其简单的 Markdown 文件实现了可持续演化的记忆系统**，把“记忆管理”从黑盒向量库变成了可观察、可编辑、可审计的工作空间。 ([OpenClaw](https://docs.openclaw.ai/concepts/memory?utm_source=chatgpt.com))
